# 质量、安全与发布核对

先读 [开发规范](../../../engineering/DEVELOPMENT_STANDARDS.md)，按当前变更范围选择有意义的验证。

- 检查 Go 对象职责、Controller/Service/DAO 依赖、中英双语注释和命名方法；不把 Java/PMD 专属规则套入 Go。
- 检查 MySQL 范式与冗余理由、审计、软删、删除标识前置查询索引，以及历史删除/重建/恢复唯一性。
- 复核无数据库业务互斥锁，状态迁移的旧状态/version/未删除条件和影响行数；保留普通事务与引擎内部锁。
- 验证 Redis 所有写入/续期的基础 TTL 加随机窗口，另验穿透、热点、失败与回源；对象存储分类、版本、权限和生命周期须有真实证据。
- 检查 View 与数据层分文件，响应式本地表单、统一请求、契约和错误状态；前端不包含云端长期密钥。
- 按需求验证鉴权与对象权限、注入、幂等、状态竞争、参数边界、失败路径和适用的平台构建。

执行 [harness](../../../engineering/harness/README.md)，处理机器阻断项并补齐人工审查和实际测试。无源码应明确跳过；不能把文件验证当作 Skill 行为评估或应用运行验证。

只有实际发布任务存在时核对环境、密钥、备份、监控、回滚及操作权限。本 Skill 本身不授予发布或部署权限，不回显凭据，不绕过失败检查。
