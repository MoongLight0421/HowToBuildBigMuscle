# API 与数据模型

先读 [开发规范](../../../engineering/DEVELOPMENT_STANDARDS.md)。从当前已确认用户流程抽取实体，不凭 Skill 预置业务需求。

- 契约明确身份与权限、分页、金额单位、时间、空值、状态、错误、幂等及兼容性；前端 Mock 服从相同契约。
- MySQL 8.0+ 以 3NF 为目标，性能需要时允许有依据的 2NF 和主表冗余，记录权威来源、同步和修复方式。
- 每张业务表独立 id、四审计字段和 is_deleted。普通查询、关联与更新排除删除记录，组合查询索引删除标识前置；唯一性另验重复删除、重建、历史及恢复。
- 不用数据库实现业务互斥。并发状态通过 version、旧状态和未删除条件原子更新，检查影响行数及冲突路径。
- Redis 应用数据基础 TTL 加随机窗口，查无与失败分开；对象存储分别记录对象键、业务版本、云端版本及必要校验值。
- 管理端与顾客身份隔离；数据层校验/转换接口响应后交给 View，不由页面猜测缺值或伪造业务数字。

按需输出数据字典、API、状态或迁移方案。运行 [harness](../../../engineering/harness/README.md)，将 SQL 实际执行、并发、查询计划和缓存验证单独记录，未执行的项目标为未运行。
