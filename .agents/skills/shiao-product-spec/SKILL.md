# 产品需求与交付规划

先读 [开发规范](../../../engineering/DEVELOPMENT_STANDARDS.md)，再核对当前任务认领和原始需求。区分已确认、建议和待确认，不把原型、会议候选或 Mock 数值当成生产事实。

- 把页面行为、角色、状态流转、正常/异常路径、权限边界和非目标整理成可实现故事。
- 对齐前端页面/Mock、API 契约、表设计与服务实现；两端共享订单、库存、退款等领域规则，不各造一套状态。
- 登录、支付和并发状态流转等关键流程补充时序说明；识别外部服务、设计稿和伙伴模块依赖。
- 完成项附测试或验收证据，不重复生成；明确缺陷或变更任务可以按范围重新打开。

输出与任务复杂度匹配的需求说明、故事、验收和依赖清单。未确认事项保持待确认，不能因本 Skill 自动创建资源、发送消息、发布或部署。技术文档变更后运行 `make check`，如实记录无源码或未运行边界。
