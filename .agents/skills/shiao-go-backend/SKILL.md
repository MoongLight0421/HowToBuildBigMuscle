# Go 后端实现与审查

先读 [开发规范](../../../engineering/DEVELOPMENT_STANDARDS.md)。遵循真实 go.mod 和当前代码；没有源码或明确契约时产出可审查方案，不创建臆造业务或宣称编译成功。

- 按 Controller → Service → DAO 分层，结构体方法、组合和小接口表达职责，依赖显式注入。Controller 不直接访问 SQL/ORM、缓存或存储 SDK，DAO 不反向依赖上层。
- 优先命名方法，尽量少用函数参数组织业务，不在实参中塞长匿名函数或嵌套回调。标准接口必要回调可传命名函数或方法。
- 每个手写函数和方法都有准确中英双语注释，覆盖用途、参数、返回及适用的错误与副作用；显式错误处理、取消、超时和事务边界。
- MySQL 8.0+ 保留审计、软删和历史唯一性要求；不用数据库业务锁，并发状态使用 version、旧状态条件及影响行数判断。
- Redis 所有应用数据写入与续期统一处理基础 TTL 加随机窗口，另验穿透/回源；对象存储区分目录、业务版本和云端版本。

按风险执行单元、集成和竞态检查，复核鉴权、对象权限、幂等、参数化查询及日志脱敏。运行 [harness](../../../engineering/harness/README.md)并报告实际执行证据；静态扫描不替代真实编译与中间件验证。
